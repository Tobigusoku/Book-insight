# Book Insight

書籍を検索して「積読」「読了」を記録する、個人開発の読書記録アプリです。Webアプリの基礎を学びながら、バックエンド・データベース・データ活用まで段階的に作ることを目指しています。

> 開発中です。画面はExpress APIを通じて本を記録します。保存先はサーバーのメモリなので、APIサーバーを再起動すると記録は消えます。以前の `localStorage` の記録は読み込みません。

## 現在できること

- 国立国会図書館サーチの OpenSearch APIで本を検索し、候補からタイトル・著者を入力できます。見つからない本は手入力できます。
- 検索候補にISBNがあれば、Open Libraryの書影を検索結果に表示します。候補を選んで登録すると書影URLも記録に保存し、一覧で表示します。画像がない・取得できない場合は代替表示にします。
- 本を積読または読了として登録し、一覧表示、タイトル・著者の編集、削除ができます。一覧では本を押すと状態・評価・読了時期・メモと操作ボタンが開きます。
- 読了した本に1〜5の評価、読了時期（年月日・年のみ・不明）、任意のメモを記録・編集できます。
- 画面からExpress APIを呼び、`POST /api/books` で登録、`GET /api/books` で一覧取得、`PATCH /api/books/:id` で更新、`DELETE /api/books/:id` で削除できます。通信失敗時はエラーを表示し、失敗した変更は画面に反映しません。
- 本の記録はAPIサーバーのメモリに一時保存します。ブラウザの再読み込みでは残りますが、APIサーバーの再起動で消えます。

## 技術構成

| 領域 | 現在使用している技術 |
| --- | --- |
| 画面 | React、JavaScript/JSX、Vite、CSS |
| 書籍検索・書影 | 国立国会図書館サーチ OpenSearch API、Open Library Covers |
| API | Node.js、Express |
| テスト | Vitest、React Testing Library、jsdom、HTTP通信を使うAPIテスト |
| 保存 | APIサーバーのプロセス内メモリ（DBは未実装） |

現状のデータの流れは次のとおりです。

```text
ブラウザ（React） ──検索──> 国立国会図書館サーチ
       │                         └─ ISBNからOpen Libraryの書影URLを生成
       └──記録の操作──> Express API（POST・GET・PATCH・DELETE /api/books） <──> サーバーのメモリ
```

PostgreSQLによる永続化、分析・推薦、他メディアへの拡張は未実装です。サーバーの記録は再起動すると消えます。

## ローカルで動かす

Node.jsとnpmが必要です。リポジトリのルートで依存関係をインストールします。

```bash
npm ci
```

2つのターミナルで、それぞれAPIサーバーとViteを起動します。

```bash
npm run dev:server
```

```bash
npm run dev
```

Viteが表示するURL（通常は `http://localhost:5173/`）で画面を開きます。開発中の `/api` リクエストはViteから通常 `http://localhost:3001` のAPIサーバーへ転送されます。`POST /api/books` はJSONの `title` と `author` が必須で、`status` は省略すると積読です。任意の `coverUrl` はHTTP(S)のURLまたは `null` を受け付けます。読了の場合は `rating`（1〜5、省略時3）、`readDate`（年月日・年のみ・`null`）、`memo`（省略時は空文字列）も指定できます。成功時は `201` と作成した本、入力不正や壊れたJSONには `400` を返します。`GET /api/books` は登録順の一覧を `200` で返し、未登録なら空の配列を返します。

`PATCH /api/books/:id` は変更したい項目だけをJSONで指定します。タイトル・著者・書影URLの修正、積読から読了への変更、評価・読了時期・メモの修正に対応します。成功時は更新後の本を `200` で返し、不正な値は `400`、対象がなければ `404` です。読了から積読へは戻せません。`DELETE /api/books/:id` は指定した本を削除し、成功時は本文なしの `204`、IDが不正なら `400`、対象がなければ `404` を返します。

読了として登録するJSONの例です。年のみは `{ "precision": "year", "value": "2020" }`、年月日は `precision` を `day`、`value` を `YYYY-MM-DD` にします。不明なら `readDate` は `null` です。積読には読了用の項目を指定しません。

```json
{
  "title": "雪国",
  "author": "川端康成",
  "status": "read",
  "rating": 5,
  "readDate": { "precision": "year", "value": "2020" },
  "memo": "また読みたい",
  "coverUrl": null
}
```

## テストと確認

```bash
npx vitest run --pool=forks
npm run lint
npm run build
```

画面のテストは外部検索APIと書籍APIの応答をモックし、入力・検索・登録・編集・削除・通信失敗を確認します。APIのテストは実際のHTTPリクエストで正常系と入力エラーを確認します。

## 今後の方向

次はローカル環境でPostgreSQLを導入し、既存のExpress APIの保存先を段階的に切り替えます。ReactとExpressの役割分担は維持し、API設計・SQL・データ永続化の理解を優先します。書影の手元画像による追加・差し替え、分析や推薦、機械学習、他メディア対応は必要性を見て判断します。

### 公開・試用の方針（未実装）

書籍版の基本機能とDB保存が安定した後、友人に少人数で試用してもらい、フィードバックを得ることを目指します。一般向けの大規模公開は目的としません。公開自体は書籍版v1の完成条件ではありません。

ホスティング候補は、Reactのビルド成果物とExpressをRenderで配信し、PostgreSQLをNeonで運用する構成です。これは確定構成ではなく、導入時に無料枠・休止と復帰・ストレージ上限・データ保持・バックアップ・費用を公式情報で再確認します。フロントエンドとバックエンドはコード上の責務を分離したまま、同一ホストで配信する案も検討します。GitHub PagesやAWSの採用は必須ではありません。

友人の個別の読書記録をクラウドへ保存する前に、認証・利用者ごとのデータ分離・アクセス制御を設計します。それまではサンプルデータを使ったデモなど、安全に試用できる方法を検討します。
